# Деплой на VDS с FastPanel

Инструкция рассчитана на сервер с небольшим объёмом ОЗУ: на сервере ничего не собирается
(CSS уже скомпилирован и лежит в репозитории), Node.js работает одним процессом и занимает
**~58 МБ в простое и ~62 МБ после входов и нагрузки**, а файлы идут напрямую между браузером и S3.

Далее по тексту:
- `files.example.com` — ваш домен;
- `USER` — системный пользователь сайта, которого создаёт FastPanel;
- `/var/www/USER/data/www/files.example.com` — каталог сайта (`APP_DIR`).

---

## 0. Подготовка (один раз)

### 0.1. Swap, если ОЗУ ≤ 1 ГБ

`npm ci` на маленьком сервере может упасть по нехватке памяти. Добавьте 1 ГБ swap:

```bash
sudo fallocate -l 1G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### 0.2. Node.js 20.12+ (рекомендуется 22 LTS)

Проверьте: `node -v`. Если Node.js нет или он старше 20.12, поставьте системно (NodeSource):

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs
node -v   # v22.x
```

> В новых версиях FastPanel есть раздел **«Приложения» / «Node.js»** с выбором версии —
> можно использовать его вместо NodeSource. Главное, чтобы `node` был ≥ 20.12.

### 0.3. DNS

Создайте A-запись `files.example.com` → IP вашего VDS.

## 1. Создание сайта в FastPanel

1. **Сайты → Создать сайт** (или «Добавить сайт»).
2. Домен: `files.example.com`. Псевдоним `www` не нужен.
3. Владелец — новый или существующий пользователь (это и есть `USER`).
4. **Обработчик / тип сайта.** Здесь три варианта, в зависимости от версии FastPanel:
   - есть тип **«Node.js»** — выберите его, укажите стартовый файл `src/server.js` и порт `3000`.
     FastPanel сам будет держать процесс и проксировать запросы; тогда шаги 5 и 6 можно
     пропустить — но всё равно задайте переменные окружения (шаг 4) и проверьте, что в
     настройках приложения заданы флаги Node.js из раздела «Экономия памяти» (шаг 6);
   - есть **«Reverse proxy» / «Проксирование»** — выберите его и укажите backend
     `http://127.0.0.1:3000`. Шаг 5 сводится к проверке конфигурации;
   - есть только **PHP/статический сайт** — выберите «Статический сайт» (без PHP, чтобы не
     тратить память на PHP-FPM); проксирование настроим вручную в шаге 5.
5. Создайте сайт.
6. **SSL:** вкладка сайта **«SSL-сертификаты» → «Let's Encrypt»** → выпустить, затем включите
   **«Перенаправление HTTP → HTTPS»**. HTTPS обязателен: cookie сессии ставится с флагом
   `Secure` и префиксом `__Host-`.

## 2. Код на сервер

Подключитесь по SSH и работайте от имени пользователя сайта, а не root:

```bash
sudo -iu USER                        # или ssh USER@server
cd /var/www/USER/data/www/files.example.com
# Каталог должен быть пустым. FastPanel кладёт туда заглушку — посмотрите и удалите её:
ls -la
rm -f index.html
git clone https://github.com/aleck59/file_manager.git .
npm ci --omit=dev                    # только runtime-зависимости, без tailwind
```

> Репозиторий приватный? Создайте deploy key: `ssh-keygen -t ed25519 -f ~/.ssh/fm_deploy -N ''`,
> добавьте `~/.ssh/fm_deploy.pub` в GitHub → Settings → Deploy keys (read-only) и клонируйте
> через `GIT_SSH_COMMAND='ssh -i ~/.ssh/fm_deploy' git clone git@github.com:aleck59/file_manager.git .`

## 3. S3: бакет и ключ доступа

1. В панели S3-провайдера создайте **приватный** бакет (публичный доступ не нужен — все
   ссылки подписанные) и ключ доступа, ограниченный этим бакетом.
2. Сами параметры (endpoint, регион, ключи) удобнее всего ввести в интерфейсе после первого
   входа — шаг 7. Там есть готовые настройки для популярных провайдеров, проверка подключения
   и кнопка **«Настроить CORS бакета»**.
3. **Lifecycle (рекомендуется):** правило из `deploy/s3-lifecycle.json` удаляет брошенные
   multipart-загрузки через 2 дня (например, если вкладку закрыли посреди загрузки).
   Через AWS CLI: `aws s3api put-bucket-lifecycle-configuration --bucket BUCKET
   --endpoint-url ENDPOINT --lifecycle-configuration file://deploy/s3-lifecycle.json`
   или в панели провайдера.

| Провайдер | Endpoint | Регион | Path-style | Особенности |
|---|---|---|---|---|
| Yandex Object Storage | `https://storage.yandexcloud.net` | `ru-central1` | да | статический ключ сервисного аккаунта |
| **Cloud.ru Object Storage** | `https://s3.cloud.ru` | `ru-central-1` | **нет** | Access Key ID в формате `<tenant_id>:<key_id>`; CORS работает только на адресах `<бакет>.s3.cloud.ru`, поэтому path-style выключается автоматически |
| Selectel | `https://s3.ru-1.storage.selcloud.ru` | `ru-1` | да | |
| Timeweb Cloud | `https://s3.timeweb.cloud` | `ru-1` | да | |
| VK Cloud | `https://hb.ru-msk.vkcloud-storage.ru` | `ru-msk` | да | |
| Cloudflare R2 | `https://<account_id>.r2.cloudflarestorage.com` | `auto` | да | |
| Amazon S3 | `https://s3.<регион>.amazonaws.com` | регион бакета | нет | |
| MinIO (свой) | `https://minio.example.com` | `us-east-1` | да | |

Уточняйте endpoint и регион в документации вашего провайдера.

### Несколько хранилищ

В **Настройки → Хранилища** можно подключить несколько бакетов — у одного или разных
провайдеров. Они объединяются в **единый диск**: одно дерево папок и один список файлов.

- **Куда пойдут новые файлы** — политика «По порядку» (первое хранилище в списке, где хватает
  квоты; порядок меняется стрелками) или «Балансировка» (наименее заполненное).
- **Квота, ГБ** — сколько можно занять в этом хранилище (0 — без ограничения). Когда она
  исчерпана, новые файлы идут в следующее.
- **Принимать новые файлы** — выключите, чтобы хранилище стало «только для чтения» (например,
  старый бакет-архив): его файлы видны и доступны, но новые туда не попадают.
- **Отключить** (корзина) убирает хранилище из диска, **не удаляя файлы в бакете**.
- Если одно из хранилищ временно недоступно, диск продолжает работать с остальными и показывает
  предупреждение.

Переменные `S3_*` из `.env` (если заданы) используются только при **первом запуске** — из них
создаётся хранилище «Основное». Дальше хранилища управляются только в интерфейсе.

**Класс хранения.** У каждого хранилища есть поле «Класс хранения» — с каким классом
сохраняются новые файлы. Для Cloud.ru по умолчанию — **STANDARD** (стандартное, для часто
используемых данных); также доступны COLD, ICE, SINGLE. Пустое значение — класс по умолчанию
бакета. При перемещении файл сохраняет свой класс.

**Размер.** В списке хранилищ показывается занятый объём **всего бакета** (как в консоли
провайдера) и отдельно — сколько занимают файлы файлообменника. Квоты считаются по объёму бакета.

**CORS обязателен** — без него браузер заблокирует прямую загрузку в S3. При сохранении
нового хранилища в интерфейсе CORS настраивается автоматически; повторить можно кнопкой
«Настроить CORS бакета» или командой `npm run s3:cors`. Если провайдер не поддерживает
настройку CORS через API — внесите правила из `deploy/s3-cors.json` в его панели, заменив
`https://files.example.com` на ваш домен (разрешены только ваш Origin и `GET`, `PUT`, `HEAD`).

## 4. Минимальный `.env`

```bash
cp .env.example .env
chmod 600 .env
npm run hash-password          # введите пароль (≥ 10 символов) — получите ADMIN_PASSWORD_HASH
nano .env
```

Достаточно двух строк: `APP_ORIGIN=https://files.example.com` и `ADMIN_PASSWORD_HASH='…'`
(в одинарных кавычках — в хеше есть символ `$`). Логин администратора — `ADMIN_USERNAME`
(по умолчанию `admin`). `SESSION_SECRET` создастся автоматически.

Создайте каталог для данных приложения:

```bash
mkdir -p data && chmod 700 data
```

В нём хранятся `users.json` (пользователи) и `settings.json` (настройки из интерфейса, в том
числе ключ S3 — файл создаётся с правами `600`). Включите `data/` в резервное копирование.

**Откуда берутся настройки.** Значения из `.env` — значения по умолчанию. Всё, что меняется
в интерфейсе (**Настройки**), сохраняется в `data/settings.json` и имеет приоритет. Рядом с
каждым полем видно, откуда значение («.env», «изменено», «по умолчанию»), и есть ссылка
«вернуть из .env». Только в `.env` задаются `DATA_DIR`, `ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH`.

> **Восстановление доступа**, если пароль администратора утерян: остановите приложение,
> удалите `data/users.json` (остальные пользователи тоже удалятся), задайте новый
> `ADMIN_PASSWORD_HASH` и запустите приложение — администратор создастся заново.
>
> **Если ошиблись в настройках** (например, указали неверный адрес сайта и больше не можете
> ничего сохранить): остановите приложение и удалите нужный ключ из `data/settings.json`
> (или весь файл) — снова будут действовать значения из `.env`.

Проверка запуска вручную:

```bash
npm start
# в другом терминале:
curl -s http://127.0.0.1:3000/healthz   # {"ok":true}
```

Остановите `Ctrl+C`.

## 5. Nginx: обратный прокси на Node.js

Приложение слушает только `127.0.0.1:3000` — наружу его отдаёт Nginx FastPanel.

1. **Сайты → files.example.com → «Конфигурация»** (иконка шестерёнки / «Изменить конфигурацию»)
   → вкладка **Nginx**.
2. В блоке `server { ... }` для порта 443 найдите `location / { ... }` (и, если есть,
   `location @fallback` / проксирование на Apache или `fastcgi_pass` на PHP) и замените на
   содержимое `deploy/nginx.conf.example`, подставив свой путь вместо
   `/var/www/USER/data/www/files.example.com`.
3. Сохраните — FastPanel проверит конфигурацию (`nginx -t`) и перезагрузит Nginx.
   Если в вашей версии правка основного конфига недоступна, используйте поле
   **«Дополнительные директивы»** в том же разделе.

Ключевые моменты конфигурации:
- `proxy_pass http://127.0.0.1:3000;` — запросы уходят в Node.js;
- `X-Forwarded-For` / `X-Forwarded-Proto` — приложение видит реальный IP (нужно для
  ограничения попыток входа) — за это отвечает `TRUST_PROXY=1` в `.env`;
- `client_max_body_size 64k;` — файлы через сервер не идут, большие тела не нужны;
- `proxy_read_timeout 300s;` — переименование/перемещение многогигабайтного файла
  копирует его внутри S3, это может занять минуты;
- `/css/` и `/js/` Nginx отдаёт сам, не дёргая Node.js.

> Если включаете кэширование в FastPanel — **не кэшируйте** `/api/` и `/`:
> API отдаёт `Cache-Control: no-store`, но серверный кэш Nginx может это проигнорировать.

## 6. Запуск в фоне

### Вариант А — PM2 (проще, привычнее)

```bash
# от root (или sudo) — один раз
npm install -g pm2

# от пользователя сайта
sudo -iu USER
cd /var/www/USER/data/www/files.example.com
mkdir -p logs
pm2 start ecosystem.config.cjs
pm2 save
pm2 startup          # выведет команду с sudo — выполните её от root, чтобы PM2 стартовал после перезагрузки
```

Полезное: `pm2 status`, `pm2 logs file-manager`, `pm2 restart file-manager`, `pm2 monit`.
Ротация логов, чтобы они не съели диск:
`pm2 install pm2-logrotate && pm2 set pm2-logrotate:max_size 10M && pm2 set pm2-logrotate:retain 5`.

`ecosystem.config.cjs` уже настроен под малую ОЗУ: 1 процесс в режиме fork, флаги экономии
памяти (см. ниже), автоперезапуск при превышении 120 МБ.

### Вариант Б — systemd (рекомендуется при очень малой ОЗУ)

Демон PM2 сам по себе занимает 40–60 МБ. systemd уже есть в системе и ничего не добавляет.
Установщик сам находит Node.js (в том числе установленный через nvm), проверяет `.env`,
`node_modules` и что приложение не запущено ещё и через PM2, создаёт `data/` с правами 700,
пишет юнит, проверяет его (`systemd-analyze verify`), запускает и проверяет `/healthz`:

```bash
cd /var/www/USER/data/www/files.example.com
sudo bash deploy/install-systemd.sh --user USER --dry-run   # показать юнит, ничего не меняя
sudo bash deploy/install-systemd.sh --user USER             # установить и запустить
systemctl status file-manager
journalctl -u file-manager -f                               # логи
```

Параметры: `--dir` (каталог приложения, по умолчанию — текущий), `--node` (путь к node),
`--name` (имя службы, по умолчанию `file-manager`), `--uninstall` (остановить и удалить юнит;
файлы приложения и `data/` не трогаются). Если раньше приложение работало через PM2 —
сначала `pm2 delete file-manager && pm2 save`.

Юнит (`deploy/file-manager.service` — шаблон) запускает процесс от пользователя сайта,
ограничивает память cgroup-ом (`MemoryHigh=120M`, `MemoryMax=150M`), перезапускает при падении
и включает песочницу systemd: `ProtectSystem=strict`, `NoNewPrivileges`, без capabilities,
только сети IPv4/IPv6/unix, фильтр системных вызовов `@system-service` (проверено по strace:
все вызовы Node.js в него входят; запрещённый вызов вернёт ошибку, а не убьёт процесс).
Писать приложению разрешено только в `data/` (`ReadWritePaths`). Оценка
`systemd-analyze security file-manager` — 1.9 (OK).

### Экономия памяти: флаги Node.js и переменные окружения

Во всех вариантах запуска (`npm start`, PM2, systemd) уже заданы переменные окружения

```
MALLOC_ARENA_MAX=2
MALLOC_TRIM_THRESHOLD_=131072
```

— они заставляют glibc сразу возвращать системе освобождённую память. Это самое важное:
каждый вход по паролю (scrypt) берёт 16 МБ, и без этих переменных после нескольких входов
процесс разрастается со ~60 до 120+ МБ.

И флаги Node.js:

```
--jitless --no-expose-wasm --optimize-for-size --max-old-space-size=64 --max-semi-space-size=1
```

- `--jitless` — V8 работает без JIT-компилятора: −15…20 МБ. Приложение почти всё время
  ждёт сеть (S3), поэтому на скорость это не влияет. Без JIT отключается WebAssembly — он
  приложению не нужен (`--no-expose-wasm` лишь убирает предупреждение об этом).
- `--optimize-for-size`, `--max-old-space-size=64`, `--max-semi-space-size=1` — компактная куча.

Если запускаете иначе (FastPanel, свой скрипт) — задайте те же переменные окружения и флаги
(в FastPanel: настройки Node.js-приложения → переменные окружения и аргументы запуска node). Если когда-нибудь понадобится максимальная скорость обработки — уберите `--jitless`
(+15 МБ ОЗУ).

### Перезапуск из интерфейса

Изменения `HOST` и `PORT` в **Настройках** вступают в силу после перезапуска; там же есть
кнопка **«Перезапустить приложение»**. Она завершает процесс, а PM2 / systemd / FastPanel
запускают его заново. Если приложение запущено вручную (`npm start` в терминале), его некому
будет поднять — интерфейс об этом предупредит. Для своего менеджера процессов задайте
переменную `FM_SUPERVISED=1`, чтобы интерфейс знал, что перезапуск безопасен. Не забудьте,
что новый `PORT` нужно указать и в `proxy_pass` Nginx.

### Вариант В — средства FastPanel

Если сайт создан с типом «Node.js» (шаг 1), FastPanel сам запускает и перезапускает процесс.
Не запускайте приложение одновременно ещё и через PM2/systemd — будет конфликт порта.

## 7. Проверка

1. Откройте `https://files.example.com` → перенаправит на `/login`.
2. Войдите (логин из `ADMIN_USERNAME`). Сверху будет предупреждение «Не подключено ни одного
   хранилища S3» → **Настроить** → **Добавить хранилище**. Выберите провайдера (например,
   Cloud.ru), впишите бакет и ключи, нажмите **Добавить** — подключение проверится, CORS бакета
   настроится сам, страница обновится. Так же подключаются следующие хранилища — все они
   образуют один диск (см. ниже).
3. Откройте **Диск**, создайте папку, перетащите файл →
   прогресс-бар → файл появляется в списке, по клику — предпросмотр справа.
   Переименуйте файл (F2 или меню «⋯») и перетащите его на папку в дереве слева.
4. «Скопировать ссылку» → откройте ссылку в приватном окне — файл скачивается с домена S3.
5. Если загрузка падает с ошибкой «Нет ответа от S3» — нажмите **Настройки → Хранилища →
   «Проверить загрузку из браузера»** (иконка загрузки) у нужного хранилища. Проверка
   загрузит пробный файл так же, как браузер загружает обычные, и назовёт причину: нет правил
   CORS, страница открыта до подключения хранилища (обновите её), сайт https, а хранилище http,
   нет прав у ключа, неверная подпись или класс хранения. Правила CORS ставит кнопка
   🔑 «Настроить CORS бакета»; если провайдер их не принимает — задайте в консоли бакета
   (у Cloud.ru: бакет → CORS): `AllowedOrigin` — адрес сайта в точности (схема, домен, без `/`
   в конце), методы `GET`, `PUT`, `HEAD`, `AllowedHeader` `*`, `ExposeHeader` `ETag`.
   Сервер сам отправляет предварительный запрос CORS так же, как браузер, и, если хранилище
   отказывает, проверяет варианты: стиль адреса (path-style / `<бакет>.хост`), отдельные
   заголовки — и пишет, что именно исправить.
6. «The difference between the request time and the current time is too large» — часы VDS
   расходятся с хранилищем больше чем на 15 минут. Приложение подписывает ссылки по часам
   хранилища (и пишет об этом в журнал `[s3] Часы сервера расходятся…`), но время лучше
   исправить: `timedatectl` → `sudo timedatectl set-ntp true` (на OpenVZ/LXC время задаёт хостер).
7. Если сразу после входа снова открывается `/login` — сайт открыт по `http`, а не `https`,
   или `APP_ORIGIN` не совпадает с адресом в браузере.


## 9. Безопасность — чек-лист

Подробный отчёт об аудите, исправленных проблемах и остаточных рисках — в [SECURITY.md](../SECURITY.md).

**fail2ban** (блокировка IP после 8 неудачных входов за 10 минут):

```bash
sudo apt-get install -y fail2ban
sudo cp deploy/fail2ban/file-manager.conf  /etc/fail2ban/filter.d/file-manager.conf
sudo cp deploy/fail2ban/file-manager.local /etc/fail2ban/jail.d/file-manager.local
# для PM2: в jail.d/file-manager.local замените backend/journalmatch на logpath (см. комментарии)
sudo systemctl restart fail2ban
sudo fail2ban-client status file-manager
```

Журнал приложения содержит строки `[auth]` (входы и неудачные попытки) и `[audit]` (загрузка,
удаление, перемещение, папки, пользователи, настройки): `journalctl -u file-manager | grep audit`
или `pm2 logs file-manager | grep audit`.
